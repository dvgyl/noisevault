Simulate quantum circuits with the noise of a real device.

NoiseVault adds the measured errors of a real quantum computer to your simulation. One profile works in Qiskit, Cirq, PennyLane and Stim, and a fingerprint lets anyone rerun your numbers.

Real qubits make mistakes

A qubit is the basic unit of a quantum computer, and it holds 0, 1 or a mix of both. On a real chip, every qubit makes errors at its own rate. The manufacturer measures those rates in a regular check called a calibration, and the rates change from one calibration to the next.

Take IBM Fez as an example. The readout error is the chance that a measurement gives the wrong bit, and across its 156 qubits it goes from 0.15% to 10.6%.

Most simulators leave the mistakes out

A simulator is a program that calculates what a quantum computer would output. An ideal simulator adds no errors, so its results look cleaner than anything a real device gives. For example, a GHZ circuit links three qubits so that their measurements always agree, and every run should give 000 or 111.

With the IBM Fez profile loaded, the same circuit gives a wrong result in 27 of 1,024 runs. Those wrong runs are the effect you want to study, and an ideal simulator never shows them.

One profile, four simulators

Each simulator describes noise in its own format. NoiseVault keeps the measured numbers of one device on one date in a single file, called a profile. It then builds that profile into the noise model of Qiskit, Cirq, PennyLane or Stim, so the same numbers reach whichever simulator you use.

nv check runs four small circuits through each conversion and compares the results with an exact reference calculation. All four pass for IBM Fez. A pass means the conversion matches the model, which is a different question from whether the model matches the hardware.

A fingerprint pins the numbers

Every profile has a fingerprint, which is a SHA-256 hash. It is a 256-bit code calculated from every number in the profile. Change one gate error of IBM Fez by 1%, and 116 of the 256 bits change.

Put the fingerprint in your paper. When a reader loads the profile with it, NoiseVault checks the numbers and stops with an error if they differ. As a result, the reader gets exactly the noise that you used.

Every conversion says what it lost

A simulator can't always represent every effect that a calibration measures. So each conversion comes with a report, saved next to your results, that sorts the noise into what is exact, approximated, clamped or missing. Nothing gets approximated without a line in the report.

Compare with a real device

nv compare scores a profile against counts measured on a device. It fits two factors, which say how much the gate errors and the readout errors must be multiplied to match the counts. Each factor comes with a 95% interval.

In this example the counts are simulated with known factors, and both intervals contain the true values. No counts from a real device have been compared yet.

25 devices, ready offline

The package includes 25 devices. They are 18 from IBM, 5 from Quantinuum and 2 from Google, and they load offline with no account. When you need a newer calibration, nv pull gets it from IBM.

Get started

  1. 1

    Try it without an install

    This needs uv. It prints the IBM Fez profile.

    Terminal
    $ uvx --from noisevault==__VERSION__ nv show ibm_fez
  2. 2

    Install for your simulator

    Use cirq, pennylane or stim in place of qiskit.

    Terminal
    $ pip install "noisevault[qiskit]==__VERSION__"
  3. 3

    Simulate with real noise

    This is the GHZ circuit from above, and it runs offline.

    ghz.py
    from qiskit import QuantumCircuit, transpile
import noisevault as nv

sim = nv.load("ibm_fez").to_qiskit()

ghz = QuantumCircuit(3)
ghz.h(0)
ghz.cx(0, 1)
ghz.cx(1, 2)
ghz.measure_all()

compiled = transpile(ghz, sim, seed_transpiler=1)
counts = sim.run(compiled, seed_simulator=1).result().get_counts()
print(counts)

What the model leaves out

The models use average error rates and treat each error as independent. So they don't include the effects below.

  • Crosstalk

    An operation on one qubit disturbs its neighbors.

  • Leakage

    A qubit leaves its two working states.

  • Coherent errors

    Small rotation errors add up in a systematic way.

  • Idle noise

    Errors while a qubit waits, unless the circuit has explicit delays.

  • Correlated readout

    Readout errors that depend on each other.

The model approximates the hardware, and it is not a copy of it. The limitations page gives the full list.
